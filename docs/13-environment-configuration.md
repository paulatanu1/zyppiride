# 13 — Environment Configuration Guide

## Build-time flags

Configured via `--dart-define=KEY=VALUE` at `flutter run` / `flutter build` time. Read in code through `String.fromEnvironment` / `bool.fromEnvironment`.

| Flag | Default | Where consumed |
|---|---|---|
| `E2E_TEST_MODE` | `false` | `lib/core/constants/test_mode.dart` — when `true`, all collection accesses (`users`, `vehicles`, `bookings`, `drivers`) are prefixed with `e2e_test_` so integration tests run against an isolated Firestore namespace. Also bypasses OTP and email verification gates. |
| `TEST_COLLECTION_PREFIX` | `e2e_test_` | Override the prefix above. |

### Examples

```bash
# Normal development against the live Firestore namespace
flutter run

# E2E test mode with isolated collections
flutter run --dart-define=E2E_TEST_MODE=true

# E2E test mode with a custom prefix (e.g. per-CI-run)
flutter run --dart-define=E2E_TEST_MODE=true --dart-define=TEST_COLLECTION_PREFIX=ci_$(date +%s)_
```

## Per-platform configuration files

| File | What it carries | Generated by |
|---|---|---|
| `lib/screens/firebase_options.dart` | Per-platform `apiKey`, `appId`, `messagingSenderId`, `projectId` | `flutterfire configure` (FlutterFire CLI) |
| `android/app/google-services.json` | Android Firebase config | Firebase Console → Project Settings → Android app |
| `ios/Runner/GoogleService-Info.plist` | iOS Firebase config | Firebase Console → Project Settings → iOS app |
| `android/app/build.gradle.kts` | Android build, package name, signing config | manually edited |
| `android/key.properties` | Signing credentials | **never committed** — created per-environment |

> When swapping projects (dev / staging / prod), regenerate all three Firebase config files together; mixing them is the leading cause of "App Check token failed" and "PERMISSION_DENIED" errors.

## Environment modes

| Mode | App Check provider | E2E test mode | Logging |
|---|---|---|---|
| `flutter run` (debug) | `debug` provider | off | Verbose — `AppLogger` outputs (gated by `kDebugMode`) |
| `flutter run --release` | Play Integrity / App Attest | off | Silent — `AppLogger` short-circuits |
| `flutter run --dart-define=E2E_TEST_MODE=true` | `debug` provider | on | Verbose + test-mode banner |
| `flutter build appbundle --release` | Play Integrity / App Attest | off | Silent |

## Required secrets and credentials

| Secret | Where it lives | Notes |
|---|---|---|
| Android upload keystore | local file, path referenced by `key.properties` | Back up to a secure vault; loss = inability to publish app updates. |
| Android `key.properties` | local file at `android/key.properties` | Gitignored. Distribute via secure channel. |
| Firebase service-account key (Admin SDK) | Cloud IAM only — **do not download to repo** | A previous incident (commit `01b0d30`) exposed one. Rotate any key generated before that commit. |
| Google Sign-In OAuth client | Firebase Console / Google Cloud Console | Auto-managed via `google-services.json`. |
| iOS provisioning profile | Apple Developer portal | Not yet configured in this repo. |

## Permissions declared by the app

### Android (`AndroidManifest.xml` — typical for this stack)
- `INTERNET`
- `ACCESS_NETWORK_STATE` (via `connectivity_plus`)
- `ACCESS_COARSE_LOCATION`, `ACCESS_FINE_LOCATION` (via `geolocator`)
- `POST_NOTIFICATIONS` (Android 13+, via `firebase_messaging`)
- `READ_EXTERNAL_STORAGE`, `READ_MEDIA_IMAGES` (via `image_picker`)
- `RECEIVE_BOOT_COMPLETED`, `WAKE_LOCK`, `VIBRATE` (via `flutter_local_notifications`)
- `RECEIVE_SMS`, `READ_PHONE_STATE` (via `sms_autofill` for OTP retrieval)

### iOS (Info.plist keys)
- `NSLocationWhenInUseUsageDescription`
- `NSLocationAlwaysAndWhenInUseUsageDescription` (only if background location is used)
- `NSPhotoLibraryUsageDescription`, `NSCameraUsageDescription`
- `UIBackgroundModes` → `remote-notification`, `fetch`

Verify these are present in `android/app/src/main/AndroidManifest.xml` and `ios/Runner/Info.plist` before each release.

## Multi-environment strategy (recommended, not yet implemented)

The repo currently has a single Firebase project. For a proper dev → staging → prod split:

1. Create `zyppiride-dev`, `zyppiride-staging`, `zyppiride-prod` Firebase projects.
2. Use `flutterfire configure --project=zyppiride-<env>` to generate per-environment configs.
3. Wrap `firebase_options.dart` selection in a `--dart-define=FB_ENV=dev|staging|prod` switch.
4. Use Android product flavours (`dev`, `staging`, `prod`) with separate package names (e.g. `com.zyppiride.app.dev`) so dev and prod can coexist on the same device.
5. Switch `.firebaserc` to project aliases:
   ```json
   {
     "projects": {
       "default": "zyppiride-2025",
       "dev": "zyppiride-dev",
       "staging": "zyppiride-staging",
       "prod": "zyppiride-prod"
     }
   }
   ```
   Then `firebase use staging` before deploying rules/functions.

## CI environment variables (recommended)

For GitHub Actions / Bitrise / GitLab CI:

| Variable | Used by |
|---|---|
| `FIREBASE_TOKEN` | `firebase deploy --token "$FIREBASE_TOKEN"` |
| `ANDROID_KEYSTORE_BASE64` | Decoded and written to disk at job start |
| `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD`, `ANDROID_KEY_ALIAS` | Composed into `key.properties` |
| `GOOGLE_SERVICES_JSON_BASE64` | `android/app/google-services.json` — environment-specific |
| `PLAY_STORE_SERVICE_ACCOUNT_JSON` | Uploading the AAB via Gradle Play Publisher / fastlane |
